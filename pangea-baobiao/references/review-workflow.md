# 页面生成与优化流程

本文借鉴 UEDMaster（https://github.com/ysredcity/ued-master ，`skills/ued-master`，2026-11-06 读取）的工作流程、设计审计清单和交付底线，按集团报表与 Pangea 组件库的场景重新整理，用中文改写，没有逐字复制。UEDMaster 的审计正文来自 Leonxlnx/taste-skill 的 redesign skill（MIT）。

**定位**：本文只规定“怎么做、做完怎么查”。颜色、字号、栅格、组件参数等**具体取值一律以本 Skill 的规范为准**（`tokens.md`、`report-spec.md`、`components-*.md`）。本文与规范冲突时，按规范执行。UEDMaster 自己也写明：已有成熟设计系统的项目，优先用对应设计系统的规范。

## 一、哪些采用，哪些不采用

| UEDMaster 的做法 | 处理 | 原因 |
| --- | --- | --- |
| 生成后用审计清单自检；优化时按“扫描 → 诊断 → 修正”进行 | 采用 | 流程通用 |
| 浏览器截图自检，多宽度、多状态，迭代到没有明显问题 | 采用，并补充报表的分辨率 | 不凭代码想象效果 |
| 改动方向不明确时，先做 2–3 个首屏小样让用户选 | 采用 | 减少返工 |
| 默认保留原页面的内容、数据、交互和明暗主题 | 采用 | 与本 Skill“先保留原稿”一致 |
| 交付底线（点击区域、状态不只靠颜色、长内容、对比度等） | 采用 | 通用底线 |
| 强调色克制使用，多类别用不同色相，状态色只表状态 | 采用 | 与“三套颜色不混用”一致 |
| 品牌色改用 `#009689` / `#00786F` | **不采用** | 本 Skill 用 Pangea 令牌 primary-6 `#00AAA6` 等，见下文对比度说明 |
| 换成 Geist、Outfit 等“有性格”的字体 | **不采用** | 中文用 PingFang SC，数值字体按规范 |
| 背景加噪点、颗粒、网格、光晕、网状渐变等质感 | **不采用** | 报表要求信息清晰；用户明确不要底纹 |
| 打破对称、避免三等分卡片、避免左侧边栏 | **不采用** | 报表按 24 栅格，等分卡片是规范用法 |
| 用占位图库（picsum）做背景图 | **不采用** | 报表不放装饰图 |
| 换用 Phosphor、Heroicons 等图标库 | **不采用** | 只用 Pangea 3 图标库 |
| 用“不规整”的假数据显得真实 | **不采用** | 报表数据以用户提供为准，示例数据需同意并标注 |

## 二、两种用法

**从需求生成页面**
1. 先确认页面类型（PC 报表 / 会议大屏 / 移动端 / 中后台）、目标分辨率和这一屏最重要的指标。
2. 按 `SKILL.md` 第五节流程搭建：栅格 → 颜色 → 字体 → 组件 → 图表 → 图标。
3. 用第四节审计清单逐项自检，再用第五节交付底线检查。

**优化已有页面**
1. **扫描**：读源码，弄清技术栈、样式写法、构建方式（例如是否由脚本拼装、改哪个源文件）、现有组件和页面结构。改动前备份。
2. **诊断**：按第四节清单列出所有问题，每条写明位置和对应的规范条目。能量化的先量化（例如逐页统计字号、色值、间距）。
3. **修正**：在现有技术栈上做针对性修改，不推倒重写。内容、数据、交互和明暗主题默认不变。

**一版还是多版**
- 用户给了明确方向、范围清楚，或说“直接做”“你定”：直接做一版完整方案。
- 用户要求“整体优化”但没给参考或幅度：先做 2–3 个首屏小样（例如保守收敛 / 标准优化 / 较大调整），差别放在改动幅度上，每个都遵守本 Skill 规范。各附一句取舍说明，并标出推荐项，选定后再做全页。
- 无法等待回复时，按“标准优化”做一版，最后说明还有哪些方向可选。

## 三、截图自检

不以“没有报错”代替“看起来对”。每轮修改后在浏览器打开截图，看图找问题、修正、再截图。

**分辨率**
| 页面类型 | 必看 | 加看 |
| --- | --- | --- |
| 会议大屏 | 1920×1080 | 1440×900、1366×768（确认降级后不遮挡、不低于最小字号） |
| PC 报表 | 1440×900 | 1920×1080、1280×800 |
| 移动端报表 | 375×812 | 390×844、414×896 |
| 中后台 | 1440×900 | 1280×800、1920×1080 |

**状态**：下拉展开、弹窗、抽屉、悬停与按下、空状态、加载、错误、长文本。下拉类组件必须实际点开看。

**量化检查**（截图看不出的问题用脚本量）
- 逐页统计同一类文字的字号（卡片标题、小标题、数值、表格、说明文字），同一类只能有一个字号。
- 检查页面级缩放：不能每页按内容多少单独缩放，否则同一屏幕上各页字号不一致。
- 检查图标在底块里是否居中（四边距离相等），缩放或 grid 布局下容易偏。
- 首屏数一数品牌色出现的位置。

## 四、设计审计清单（报表与中后台版）

**字体与字号**
- 全站只用 `tokens.md` 字号表里的几档；同一类文字在所有页面用同一个字号，不出现 12.5px 这类非整数字号。
- 桌面端最小 12px，移动端最小 10px；主副层级相差 2–4px。
- 中文字重只用 400 / 600；数值用规范的数值字体，并开启 `font-variant-numeric: tabular-nums`，让表格上下对齐。
- 段落不要过宽，长说明文字控制在一屏宽度的一部分内，行高 1.5。
- 用 `text-wrap: balance` / `pretty` 避免标题最后一行只剩一个字。

**颜色与表面**
- 品牌色只标这一屏最该注意或点击的东西：主操作、当前选中、关键进度。标题、普通按钮、普通数字默认用中性色。
- 多个类别并列（图表系列、分类）时用图表色的不同色相，不要都改成品牌色深浅。
- 涨跌色、状态色只表达语义，不当装饰色。
- 不加底纹、噪点、光晕、装饰圆环和花哨渐变；背景、卡片、摘要带用纯色。
- 阴影用规范里的几档，光源方向一致；不要在浅色页面里突然插一块深色区域。

**布局**
- 按 24 栅格排版，卡片宽度取整数列，边距和槽宽按规范。
- 并排的卡片要对齐同类元素：标题、指标数值、图例、图表区的上沿在同一条线上；卡片底部的按钮对齐。
- 光学对齐：图标在圆形或方形底块里要视觉居中，必要时微调 1–2px。
- 会议大屏一屏展示、不滚动：先在 1920×1080 画布内把每页排进一屏（收紧间距、改并排、降低图表高度），再整页统一缩放；不为了塞进一屏而单独缩小某一页。
- 用 CSS Grid 做多列，不用复杂的百分比计算。

**交互与状态**
- 按钮、页签、表格行有悬停态，按下有反馈，键盘聚焦有可见的焦点框。
- 过渡时间 150–300ms，动画只改 `transform` 和 `opacity`。
- 导航和页签标出当前所在位置。
- 有加载（骨架屏与内容同形）、空状态、错误状态；表单错误就地提示，不用 `alert()`。
- 看起来能点的就要能点；不能用的要明确禁用，不放指向 `#` 的死链接。

**内容**
- 保留用户提供的指标名、数据、单位和口径；示例数据需要用户同意并标注“示例”。
- 文案直接、具体：错误提示写清原因和下一步，成功提示不加感叹号。
- 标题用句子式写法，不堆砌营销词。

**组件与图标**
- 优先使用 `components-*.md` 中的 Pangea 组件，不自创近似样式。
- 只用 Pangea 3 图标库，同组图标尺寸和线性 / 填充风格一致。
- 卡片只在需要层级时使用，不要层层嵌套带边框的卡片。

**代码质量**
- 用语义化标签：`header`、`nav`、`main`、`section`、`aside`。
- 自定义类名加前缀，避免和已有样式重名（例如 `.sw`、`.it`、`.r` 这类短名很容易冲突）。
- 少用行内样式；z-index 用统一的几档；删除调试代码和注释掉的旧代码。
- 页面有正确的 `<title>`；单文件离线页面把字体、图标内嵌，不依赖外网。

## 五、交付底线

- **点击区域**：桌面端可点区域不小于 24×24px，移动端不小于 44×44px；复选框、单选框的文字和控件共用点击区域。
- **反馈比静止态更醒目**：悬停、按下、聚焦的对比度不能低于静止状态。
- **加载按钮保留原文字**：进入加载时加指示，不把文字整块换成转圈。
- **危险操作可挽回**：删除、作废、批量修改要二次确认或可撤销。
- **每个界面都有下一步**：空结果、出错、完成后都给出继续或返回的入口。
- **移动端**：输入框字号不小于 16px（避免 iOS 自动放大）；不禁止页面缩放；贴边元素留出安全区 `env(safe-area-inset-*)`。
- **状态不只靠颜色**：成功、失败、预警同时有文字或图标；涨跌除颜色外还要有正负号或“改善 / 恶化”字样。
- **长短内容都不崩**：用很短、普通、很长三种内容（长指标名、长组织名、空字段）各看一遍。
- **深色主题**：在 `<html>` 上声明 `color-scheme: dark`，原生下拉框显式设置背景和文字色。
- **对比度**：按 WCAG 2.x，正文不低于 4.5:1，图标和边框不低于 3:1。

**品牌色对比度说明**：Pangea primary-6 `#00AAA6` 白底对比度约 2.9:1，primary-7 `#009093` 约 3.9:1，primary-8 `#00757B` 约 5.5:1。按本 Skill 规范，组件仍使用 Pangea 定义的令牌（例如链接文字为 primary-6）。用作大面积底色、选中指示、图标没有问题；用作白底上的小号正文文字时对比度不足，要在交付说明里注明。文字颜色一律用规范文字色（#1D2129 / #4E5969 / #86909C），不把小字号文字改成 primary-8 `#00757B`。品牌色底配白字（导航栏、主按钮）时可以用 primary-7 / primary-8 作底。

## 六、修正顺序

1. **规范对齐**：颜色令牌、字号层级、栅格与间距改成规范值。改动最大、风险最低。
2. **交互状态**：悬停、按下、聚焦、当前位置。
3. **布局与对齐**：并排元素对齐、光学居中、卡片宽度取整数列。
4. **组件替换**：自创的近似样式换成 Pangea 组件。
5. **状态补全**：加载、空状态、错误状态。
6. **细节打磨**：字距、换行、图表标签和图例。

每改一类就截图复查一次，确认没有破坏原有功能。
